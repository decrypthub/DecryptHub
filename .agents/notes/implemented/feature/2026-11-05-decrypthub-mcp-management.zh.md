# Agent Note: DecryptHub MCP 与官方组件管理

Status: implemented

[English](2026-11-05-decrypthub-mcp-management.md) | 中文

## Problem

仅具备 MCP 底层服务时，用户无法直观看到如何配置自定义工具或管理官方分析组件。安装了命令、建立了 MCP 连接和连接了目标设备也容易被混为一谈。

## Decision

自定义 MCP 和官方组件共用一个界面插件，分别进入设置页与官方组件侧栏。自定义配置复用 DSH Settings、凭据引用和 MCP manager；官方版本通过独立管理服务校验安装，组件协议继续隔离浏览器及设备实现。官方连接采用根级 volatile 配置，变更串行释放旧集成后再挂载。页面分别展示安装、传输和目标事实，未知目标保持未确认。

本决策扩展[已有 MCP manager 决策](2026-08-31-mcp-manager-plugin.zh.md)，不替代其连接监督和配置所有权；旧决策继续作为底层机制依据。

## Verification

定向测试验证导入拒绝、凭据引用、过期写入、取消、校验失败保留旧版及回滚。真实 Loader 组合验证配置可写、版本冲突拒绝及所有者权限。隔离 Electron 实例验证导入停用和管理入口。真实发布下载、手机连接及内嵌 WDH 工作台不在已验证范围。

## Alternatives considered

未采用另写 MCP 传输、直接导入其他组件内部模块或通过找到 CLI 就显示设备就绪的方案。安装页面不代替浏览器、抓包和调试工作台。

## Consequences

新增组件只有在来源、平台、路径及校验和符合约束时才能切换活动版本；失败和取消保留旧指针。所有者才能管理官方组件。新配置及卸载必须释放订阅和进程，不能让旧工作目录的工具继续处理新工作区。
