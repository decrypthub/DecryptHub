# 对话、图片与权限交互

更新：2026-10-27。浏览器、输入框命令与研究子代理见 [browser-harness.md](browser-harness.md)。

## 信息层级

会话名称来自首次用户任务：先给出不含网址的任务名称，再由当前模型异步概括。网页导航不改名；用户手动改名后，后台结果不能覆盖。标题来源持久化，改名不改变会话 ID。请求有并发/超时限制，失败不影响主任务。架构与待验收项见 [browser-architecture.md](./browser-architecture.md)。

一个用户请求对应一个 Run/turn。消息和工具操作各自有稳定 ID；流式更新按消息 ID 寻址，重复的 provider tool_call ID 不再混淆不同步骤。历史记录与重连快照使用同一套投影逻辑。

每轮显示：用户消息与附件、折叠的执行过程、最终回复。过程说明和工具交错出现时也归入同一组。工具默认显示可读名称、文件/命令摘要、结果状态和耗时；展开后查看原始工具名、参数与输出。未完成操作恢复后显示未收到结果，不自动重放，也不永久显示执行中。

模型接口明确返回的 `reasoning_content` / `thinking` 文本单独展示为“思考过程”，与工具步骤按顺序编排；进行中的过程默认展开，完成后默认收起，用户手动展开/收起的选择保持有效。思考正文可滚动阅读，支持实时增量、刷新恢复和中断保存。重试会清除同一消息中失败尝试的临时内容，避免重复拼接。未返回可读思考的模型不显示空内容；签名、加密或 redacted thinking 块不渲染。

最终回复保持普通文档排版，不为每次工具调用重复显示助手头像。用户消息靠右并显示时间；历史图片可以预览或重新加入输入框。文件改动收敛到工作区文件面板的可选 Git diff，不再显示独立的 ChangeStore 改动卡。聊天栏只查看上下文用量，不覆盖模型配置的容量。

顶部计划条可点击或通过键盘打开完整计划，列出所有步骤、完整文字和当前状态。浮层内独立滚动，支持复制为 Markdown；打开时实时跟随计划更新，切换会话立即关闭，避免把上一会话的计划带入新会话。未使用的默认计划模板不显示。

顶部不显示会话信息弹层。会话操作菜单提供“复制会话 ID”和“复制为 Markdown”；导出用户消息、可见 AI 回复、附件引用、工具调用/结果及运行 ID，默认省略思考内容、系统提示和供应商密钥配置。正在输出的回复标记为尚未完成。复制针对所操作的会话，和当前聚焦会话分别处理。

工具面板开关固定在窗口右侧的窗口控制组。聊天、工具面板、设置页和侧栏顶部共享拖动命中规则：标题与空白可拖动，按钮/页签保留点击，双击非交互区域切换最大化。输入框不显示额外焦点内框，其他控件保持键盘焦点提示。输入 `/` 即显示命令，移除独立的命令按钮；命令项为 32px 单行，保留方向键、Tab、Enter、Esc 操作。

## 图片输入

- 支持文件选择、剪贴板图片粘贴、拖入，以及仅含附件的消息。
- 支持 PNG、JPEG、WebP、静态 GIF；不支持 SVG、HEIC、PDF 等格式。图片尺寸限制为 2500 万像素、单边 16384；每文件最多 8MB，每消息最多 8 个附件、合计 20MB。
- 服务端根据文件头识别 MIME，复制为会话内的附件快照，记录大小和 SHA-256。读取时检查哈希与路径，不依赖原文件持续存在。
- 历史只保存附件 ID 与元信息；原图保存在会话的 `.attachments`。缩略图缓存有数量上限，预览大图按需读取。
- 当前模型需要启用图片输入。可从输入框提示中启用，或在模型设置中配置；若模型不支持图片，发送失败会保留附件，不悄悄改成文字发送。
- OpenAI 兼容接口使用 `image_url` data URL；Anthropic 转为 `image` + base64 source。图片 token 使用独立估算，base64 不当作普通文本计数。模型切换为文字模型时，旧图片以明确的不可见提示代替。

文件解析失败、格式不支持、数量超限等错误都在模型请求之前返回。模型端拒绝的已发送图片仍保留在用户消息中，可以重新使用附件。

## 权限交互

访问边界 `mode` 与审批方式 `review` 分开保存。界面主选项为：

| 选项 | 当前行为 |
|---|---|
| 请求批准 | 当前目录内文件读写；隔离范围之外的执行或联网由用户确认 |
| 自动批准 | 保持同样边界，对符合宿主规则的请求自动批准，其余询问 |
| 完全访问权限 | 命令、浏览器、页面脚本及已启用 MCP 直接执行；命令使用当前系统用户权限。仅当前会话、本次应用运行有效 |
| 只读查看（补充项） | 只查看文件和页面，拒绝代码执行与修改 |

当前自动规则有意保持窄范围：只有隔离执行器内、由可信 npm launcher 发起、禁用安装脚本、仅访问官方 registry 的依赖安装可以自动批准。任意 shell、未知 MCP、浏览器交互和未隔离进程都不能通过模型自报“低风险”获得批准。这是规则审批，不是宣称已经实现 Codex 的独立模型审查器。

本机 Windows 执行隔离尚未配置，界面会显示“命令逐次确认”。选择自动批准也不会掩盖这一事实。切换权限或工作目录会撤销待处理批准；工作目录验证失败时保留原绑定。
