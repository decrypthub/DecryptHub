## 信息层级

会话名称来自首次用户任务：先给出不含网址的任务名称，再由当前模型异步概括。网页导航不改名；用户手动改名后，后台结果不能覆盖。标题来源持久化，改名不改变会话 ID。请求有并发/超时限制，失败不影响主任务。架构与待验收项见 [browser-architecture.md](./browser-architecture.md)。

一个用户请求对应一个 Run/turn。消息和工具操作各自有稳定 ID；流式更新按消息 ID 寻址，重复的 provider tool_call ID 不再混淆不同步骤。历史记录与重连快照使用同一套投影逻辑。

输入区不再放项目选择与「此计算机」运行环境入口：项目与目录在侧栏管理，执行器信息只在出错时以横幅提示。

每轮显示：用户消息与附件、折叠的执行过程、最终回复。过程列表和工具 body 不再增加滚动层；工具输入、输出各自在卡片内滚动，摘要行按动作归类（思考 / 读取页面 / 写入文件…）。手动展开过程、工具或思考时释放自动贴底，保留阅读位置。工具默认显示可读名称、文件/命令摘要、结果状态和耗时；普通失败在折叠行展示首条原因，明确的命令退出保留命令摘要与退出码。展开后查看原始工具名、参数与输出。未完成操作恢复后显示未收到结果，不自动重放，也不永久显示执行中。

模型在工具调用之间输出的进度说明属于 Agent Loop，和工具按真实顺序折叠在执行过程里，展开即可看到；最终回复始终显示在过程之外。消息操作：用户消息可复制；最后一条且该轮没有工具调用时可直接编辑并重新发送（替换原消息重新执行）。最终回复底部固定显示复制、有帮助 / 没帮助、本次用量与时间（中间说明不重复显示用量），赞踩按消息持久化到会话。输入框默认两行高，内容换行时自动增高，发送后回到两行。

任务运行中按运行参数的 busy-Enter 策略进入下一轮队列或作为本轮插话；Enter 和发送按钮一致，Cmd/Ctrl+Enter 使用相反策略，空草稿时可批量插话。队列贴在输入框上方，只有一条时直接显示内容和分开的编辑 / 删除 / 插话按钮；多条默认折叠。插话在下一 Agent 步骤边界领取，不能中断正在执行的工具；先写历史再确认队列，保持原问题及同轮消息顺序。编辑保存全文，停止后保留尚未领取的队列，等待手动继续。队列持久化到会话状态，刷新和重启后仍在。停止按钮、双 Escape 与运行中的 `/stop` 绑定当前轮次；生命周期内部的整体中断仍可清空队列。

流式 Markdown 保留稳定区块和代码行，定稿不整体重建回复节点。滚动统一观察内容和视口：位于物理底部时跟随，用户上翻或展开内容时保留阅读位置，滚回底部恢复跟随。冷态上下文读取保存样本或被动估算，未知容量不显示假 0%。本轮最后回复后根据文件工具的成功记录显示文件卡片、净增删行数，并可打开记录前后比较；shell 或外部程序写入不保证被此记录覆盖。

双 Escape 在同一会话、同一轮次、同一对话区域中于 500ms 内连续按下才生效；菜单、对话框、审批/回答等待、终端、输入法、组合键、按键重复与焦点切换都不能形成停止序列。实现依据与本机验证边界见 [源码对齐记录](ui-source-alignment-20261104.md)。

模型接口明确返回的 `reasoning_content` / `thinking` 文本单独展示为“思考过程”，与工具步骤按顺序编排；思考过程默认收起，进行中的轮次展开执行过程，完成后连同一行摘要一起收起，用户手动展开/收起的选择保持有效。思考正文可滚动阅读，支持实时增量、刷新恢复和中断保存。重试会清除同一消息中失败尝试的临时内容，避免重复拼接。未返回可读思考的模型不显示空内容；签名、加密或 redacted thinking 块不渲染。

最终回复保持普通文档排版，不为每次工具调用重复显示助手头像。用户消息靠右并显示时间；历史图片可以预览或重新加入输入框。文件页显示当前工作目录的实际路径；Git 改动界面暂不提供，也不显示独立的 ChangeStore 改动卡。聊天栏只查看上下文用量，不覆盖模型配置的容量。

目标和计划入口放在会话标题右侧，不在消息区或输入框上方另外占据整行。默认只显示目标状态和计划完成数；长目标、当前步骤、证据和操作在点击或键盘打开后查看。目标成功设置、暂停、继续和清除不额外显示成功横幅，失败仍明确反馈。窄聊天栏精简按钮文字，保留可访问名称和悬停说明。

完整计划浮层列出所有步骤、完整文字和当前状态，内部独立滚动，支持复制为 Markdown；打开时实时跟随计划更新，切换会话立即关闭，避免把上一会话的计划带入新会话。未使用的默认计划模板不显示。目标详情保留完整目标、完成条件、证据和下一步，以及暂停、继续、结束操作；切换会话同样关闭，不改变目标执行和授权边界。

顶部不显示会话信息弹层。会话操作菜单提供“复制会话 ID”和“复制为 Markdown”；导出用户消息、可见 AI 回复、附件引用、工具调用/结果及运行 ID，默认省略思考内容、系统提示和供应商密钥配置。正在输出的回复标记为尚未完成。复制针对所操作的会话，和当前聚焦会话分别处理。

工具面板开关固定在窗口右侧的窗口控制组。聊天、工具面板、设置页和侧栏顶部共享拖动命中规则：标题与空白可拖动，按钮/页签保留点击，双击非交互区域切换最大化。输入框不显示额外焦点内框，其他控件保持键盘焦点提示。输入 `/` 即显示命令，移除独立的命令按钮；命令菜单按用途分组，每行依次显示图标、中文名称、命令名与说明，保留方向键、Tab、Enter、Esc 操作。已识别的开头命令单独着色，实际执行结果在对话流中显示；压缩进行中与完成后的检查点共用一个位置，不再在输入框上方重复摆放状态条。

## 图片输入

- 支持文件选择、剪贴板图片粘贴、拖入，以及仅含附件的消息。
- 支持 PNG、JPEG、WebP、静态 GIF；不支持 SVG、HEIC、PDF 等格式。图片尺寸限制为 2500 万像素、单边 16384；每文件最多 8MB，每消息最多 8 个附件、合计 20MB。
- 服务端根据文件头识别 MIME，复制为会话内的附件快照，记录大小和 SHA-256。读取时检查哈希与路径，不依赖原文件持续存在。
- 历史只保存附件 ID 与元信息；原图保存在会话的 `.attachments`。缩略图缓存有数量上限，预览大图按需读取。
- 当前模型需要启用图片输入。可从输入框提示中启用，或在模型设置中配置；若模型不支持图片，发送失败会保留附件，不悄悄改成文字发送。
- OpenAI 兼容接口使用 `image_url` data URL；Anthropic 转为 `image` + base64 source。图片 token 使用独立估算，base64 不当作普通文本计数。模型切换为文字模型时，旧图片以明确的不可见提示代替。

文件解析失败、格式不支持、数量超限等错误都在模型请求之前返回。模型端拒绝的已发送图片仍保留在用户消息中，可以重新使用附件。

## 图片输出（AI 发给用户）

模型可以主动把图片放进回复里，不需要用户先发图。三种来源都收敛到同一个渲染通道：

| 来源 | 触发 | 图片挂在哪 |
|---|---|---|
| `take_screenshot` | 模型要看页面版式时 | 该工具条下方（展开执行过程可见） |
| `reply_image` | 模型要给你看工作区里的图或图表 | 同上；正文没指定位置时附在回复末尾 |
| 外部 MCP 返回的 image block | 已连接的 MCP 服务回图 | 同 `reply_image` |

**正文定位**：模型可以写 `![说明](image:<附件id>)` 把图片放到正文某处，`reply-markdown.jsx` 按 `image-refs.js` 切段，图片只出现在它指定的位置，不重复附在末尾。id 不是本会话真实图片附件时，这段语法原样留在文本里，不会变成坏图。

**存储与安全边界**（这几条是硬约束，改动时不要放松）：

- 图片走**和用户附件完全相同**的存储：登记到会话 `.attachments/<id>/`，记大小与 SHA-256；事件与历史里**只有附件 id 与元信息**，`base64` 既不进 `.agent-history.json`，也不进 IPC 事件、不进工具输出文本。UI 按 id 调 `attachment-preview` 取 dataUrl（复用了现成的懒加载、缩略图缓存与大图预览）。
- 只接受**工作区内的本地路径**或本会话已有的图片附件。远端 URL、`data:` URL 一律拒绝——模型能决定屏幕上出现什么，不能让这个决定由外部地址驱动。
- 格式按**文件头真实嗅探**（`inspectImage`），不看扩展名；SVG 被拒（可内嵌脚本）。单张 ≤8MB，每次 ≤4 张。
- 回复图片带「AI 提供」标记，与用户自己的附件区分开，降低伪造截图冒充系统提示的风险。
- 图片只给用户看，**不回喂模型**：OpenAI 的 `tool` role 普遍不接受图片数组，历史重放会 400。

定向验收：`npm run check:reply-images`（真起 sidecar + 真前端 + Chrome，断言渲染、正文定位、重载恢复与历史无 base64）。单测在 `sidecar/test/reply-image.test.mjs`。


## 权限交互

权限以**预设**呈现：一个预设 = 「访问边界 `mode`」+「审批方式 `review`」两个旋钮的捆绑
（实现见 `sidecar/permission-presets.mjs`，对照 DeepSeek Harness 的
`packages/interaction/permission-presets`）。可选三档，顺序固定：

| 预设 | `mode` / `review` | 当前行为 |
|---|---|---|
| 仅可查看 | `read-only` / `manual` | 只读工作区文件与页面；写入、执行代码与远程修改直接拒绝，不弹确认 |
| 工作区内修改（默认） | `standard` / `manual` | 工作区内读写直接执行；隔离范围之外的执行、联网与浏览器交互由用户确认 |
| 完全权限 | `full-access` / `manual` | 命令、浏览器、页面脚本及已启用 MCP 直接执行；命令使用当前系统用户权限 |

三档之外还有一个**推导出来**的当前值：`review=auto`（规则自动批准）不匹配任何预设，界面把它显示为「自动批准」，
但它不出现在可选行里，也不能被选中——这正是 DSH 对 `custom` 的处理。规则自动批准的范围有意保持窄：
只有隔离执行器内、由可信 npm launcher 发起、禁用安装脚本、仅访问官方 registry 的依赖安装会被自动批准。
任意 shell、未知 MCP、浏览器交互和未隔离进程都不能通过模型自报"低风险"获得批准。

**完全权限需要勾选确认**：选择它时会弹风险确认框，「启用完全权限」按钮在勾选「我已了解风险，并愿意继续」之前
一直是禁用的（DSH `RiskConfirmation` 的同款门禁）。显式键入 `/permission danger-full-access` 视为明确同意，
不再弹框——这与 DSH 一致。

**完全权限随会话保存**：重启应用后仍是完全权限，直到用户改回来。这是 2026-11-02 由用户决定与 DSH 对齐的改动；
此前是「仅本次应用运行有效，恢复聊天时降为标准」。

`/permission` 是唯一的命令行入口：不带参数报告当前预设与可用项，带参数直接切换。
预设的对外名是 DSH 的 machine value（`read-only` / `workspace-write` / `danger-full-access`），
同时接受历史内部名（`standard` / `full-access`）。界面、`/status` 与模型可见的状态说明共用同一个预设名，
不会出现「界面写工作区内修改、模型看到 standard」这种两套叫法。

本机 Windows 执行隔离尚未配置，界面会显示"命令逐次确认"。权限可在任务运行中切换：下一次工具调用按新权限判定，升到完全权限会放行当前等待中的批准，降级不打断后台任务；切换工作目录会撤销待处理批准，工作目录验证失败时保留原绑定。

## 验证

长任务和恢复机制见 [long-running-agent.md](./long-running-agent.md)。临时模型故障共用最多10次重试预算，执行过程显示次数和重连等待，刷新可恢复；停止立即取消等待。目标详情支持完整查看完成条件、模型记录的证据、下一步和进展记录。内部接续事件不作为用户消息展示。

2026-10-27 浏览器呈现回归：202 项核心测试通过，覆盖思考流、消息/会话身份、重连快照、中断保存、重试去重、取消退避、供应商流中断以及会话布局持久化。浅深主题 UI 验证覆盖光晕、具名浏览器菜单、思考流在刷新和切换会话后的恢复、HTML 转义，以及各会话的独立页签/宽度。Windows 独立测试窗口中已观察到真实嵌入页面周围的光晕、思考文字、菜单开关和页面恢复；视觉夹具仅使用本地响应流和独立 WebView 数据，正常浏览器/抓包/调试通路另由原生回归脚本验证。

运行时测试覆盖消息 ID、重复工具 ID、历史迁移、部分回复恢复、图片格式与越界、附件跨会话隔离、图片真实 HTTP 请求、token 估算和审批规则。UI 测试通过本地模拟模型验证：选择/粘贴/拖入图片 → 图片独立发送 → 模型收到图片字节 → 回复显示 → 页面重载后图片与回复保留。深浅主题均检查工具折叠、预览关闭与焦点恢复、按钮点击区域、文字对比度与窄窗口布局。
