# 长任务、模型恢复与交互收敛

日期：2026-10-28。本文记录本轮实现决定、兼容方式和未完成项，不代表与其他产品能力等价。

## 依据与取舍

- [Codex Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)：目标是会话持久状态，接续只发生在空闲边界；完成依据证据，用户输入、停止和预算优先；无工具工作时应阻止自动空转。
- [DeepSeek Harness Goal 分组](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/goal)：目标状态、模型工具、人类命令和 round driver 分别拥有职责，不能把目标直接等同于循环发消息。
- [ZCode 协议](https://github.com/zai-org/ZCode/blob/main/docs/zcode-protocol.md)：运行时是消息、队列、用量、目标的事实源，UI 仅保存展示状态。
- [ZCode 模型恢复设计](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/design/v2/model/stream-error-retry.md)：统一重试预算、可见重试阶段、区分空响应和终止原因，避免不同层的重试相乘。

这些资料用于设计比较，没有复制第三方实现。公开文档能说明契约，不能证明闭源桌面端的内部实现。

## 本轮决定

### 一次逻辑请求，一个十次重试预算

首次请求之外最多重试10次；不是各层分别重试10次。Agent 请求在决策层持有预算，底层适配器只负责一次传输和有界协议兼容；标题、压缩等直接模型调用走同一个请求恢复函数，标题仍受其12秒取消边界限制。子代理也使用 Agent 的相同恢复机制。

网络中断、空闲超时、408/409/425/429及5xx恢复；认证、权限、无效参数和输出限制直接给出可处理的错误。指数退避带小幅抖动，通常最多30秒，服务端 Retry-After 最多等待5分钟；等待可以立即取消。配置兼容的400协商（如不支持 stream_options）最多各一次，不视为临时服务失败。

响应流没有正常结束或空返回不能当作任务完成。失败的工具参数增量不能执行；只有完整模型结果进入工具执行。重试不重放已执行工具。恢复沿用同一显示项并清空失败的临时文字。重试事件进入所属 Run journal，UI 显示次数、倒计时，并可从会话快照恢复；重试提示不重复记录服务端正文或凭据。

### 目标状态与调度分离

`goals.mjs` 持有状态转换、模型上下文投影和独立 GoalDriver。Session 仍拥有工作区、Run、队列与工具授权，仅编排生命周期。

用户通过 `/goal` 或目标对话框建立持续目标。普通任务仍可自主规划和执行，不要求用户先设目标；不能从网页、文件或工具返回值启动无限后台工作。模型通过 `goal_update` 自主记录完成条件、已验证状态、证据、下一步和进展摘要。

完成必须显式更新 complete，同时提供非空完成条件和证据列表，全部条件必须 verified；有研究子代理未回收时不能完成。宿主检查结构和生命周期；证据内容仍是模型报告，不是独立审计器，不宣称已由程序证明每条结论真实。用户可展开目标查看完整条件、证据、下一步、最近30次进展和累计用量。

目标上下文在每次模型请求时从持久状态派生，压缩聊天不会删除目标。自动接续记录为 `continuation` 内部事件，不伪造用户消息，也不产生“继续完成当前目标”的用户气泡；协议适配视图仍需把内部接续转换成模型接受的消息角色。

Driver 只在当前会话/工作区/目标批次仍有效、Run 已结束、无排队消息、审批和提问时接续。用户消息优先，停止/清除/关闭会话会取消已调度接续；异步晚到结果不能启动替换后的目标。自动轮没有工具工作或新的目标进展时停止空转，明确显示需处理。预算用尽是暂停，不是完成。

### 兼容和退出条件

旧目标保留 ID、摘要、状态和用户预算，缺失的新字段使用空列表。重启后活动目标暂停且保留原进展，需用户恢复；不自动重放副作用。旧聊天历史保持原样，新版隐藏的是新生成的内部接续事件，没有删除以前的用户记录。

退出条件：真实本地HTTP服务证明首次加10次请求；覆盖流中断、空响应、永久错误、退避取消和工具不重放；目标覆盖停止、替换、用户队列优先、预算、无进展、压缩及恢复；运行完整 sidecar 测试、UI构建/审计/深浅主题验收和打包检查。

## 从用户体验看，仍值得投入的改进

| 优先级 | 差距 | 建议验收标准 |
|---|---|---|
| P1 | 用户补充目前进入下一轮队列，长轮中途调整不够及时 | 在工具批次边界安全注入明确的人类补充，保持同一任务与权限；不终止已提交副作用、不遗失排队消息 |
| P1 | 长分析缺少统一证据/产物索引 | 文件、请求、脚本hash、实验和结论之间可跳转；区分已验证、假设、失败路径；重启后可检索 |
| P1 | 模型报告完成条件不等于独立验收 | 增加可选的无副作用 verifier，用真实测试/回放结果审查完成声明，记录审查成本与失败原因；不能只找另一模型说“通过” |
| P1 | 恢复入口分散 | 会话内展示最后安全检查点、未完成工具、后台进程和恢复动作；绝不盲目重放网络提交、安装和设备写入 |
| P1 | 研究子代理仅只读且固定10步/5分钟 | 将预算、取消、结果引用和主代理验收标准化；需要写入时先建立独立工作区/工作树和冲突处理，再开放写代理 |
| P2 | 上下文、缓存、失败请求成本缺少统一账目 | 按请求/重试/压缩/子代理分类显示真实provider usage；无法取得用量时明确未知，不能假报零消耗 |
| P2 | 扩展开发与兼容回归尚不成熟 | 提供有版本的插件契约、能力声明、安装回滚、诊断和固定回放集；CLI和MCP独立维护，核心不导入设备模块源码 |
| P2 | 原生浏览器浮层、IME、多屏等仍有平台差异 | 按浏览器能力和Windows真实矩阵验收；独立内核与显示后端继续解耦，避免仅为外观大规模替换技术栈 |

本轮先收敛请求恢复、目标生命周期和界面反馈。未接入新的模型/设备服务，也未宣称实现通用JSVMP去虚拟化或完整写入子代理。

## 本轮本机验证

215项 sidecar 测试通过；UI构建、静态审计、深浅主题完整交互检查通过，包含目标详情、模型故障恢复提示和退避期间刷新恢复。Windows发布JS bundle与捆绑Node冒烟通过；桌面调试程序已重建，真实原生浏览器的有头启动、DOM、抓包和调试通路通过。模型故障与自主目标使用本地受控HTTP/工具夹具，不宣称验证了每个外部供应商或复杂目标的实际成功率。
