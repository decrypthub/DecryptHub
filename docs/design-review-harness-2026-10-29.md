# Harness 对照体验审视与改版依据

日期：2026-10-29；2026-10-30 补充 Mac 实机观察。用户要求先深入熟悉 DeepSeek Harness，系统判断 DecryptHub 的不足，再设计下一轮改动。本次产出为体验审视和改版规格；产品代码仍为上一轮版本。

## 结论

当前界面已具备项目归属、消息分轮、工具展开、轮次刻度和子代理入口，但各功能还缺少统一的阅读与操作规则。上一轮更关注控件和功能闭环，对长任务中持续阅读、查看细节、返回原位置的比较不够。自动检查通过能够证明所覆盖的行为正常，不能证明整体版式和阅读体验已经对齐参考产品。

接下来的设计单位应是一条完整工作流：选择项目 → 发起任务 → 观察进度 → 阅读结果 → 查看工具/子代理证据 → 返回正文。每一步都要有固定的位置、明确的层级和稳定的返回路径。

## Harness 中值得学习的组织方式

1. **阅读与检查有不同层级。** 对话正文保持连续；一轮工作先概括，再展开过程；轨迹另有面向诊断的请求列表与详情。默认阅读不要求理解 JSON。
2. **长内容有明确的归属和高度规则。** `ChatGroupSeat` 的默认过程区为 `min(400px, 50vh)`，支持进一步展开；大量工具不必全部铺入主阅读区。
3. **索引与实际位置绑定。** 预览锚定指向的刻度，并限制在消息可见带内；索引处理自身滚动、焦点和历史加载，而非仅画一列短线。
4. **工具和产物有语义呈现。** 原生的文件读取、终端和 diff 组件区分了内容类型；最终文件变更摘要是可进入审阅的结果入口。
5. **父子会话可追溯。** 子代理目录和面包屑支持查看子会话及旁侧打开，当前会话身份明确。
6. **设置按使用目的组织。** 具有工作步骤展示密度、自动收起时机、字号、输入期间的消息处理等偏好，影响的是整条工作流。

参考产品同样存在取舍：本机展开右侧工作面后，中间正文会明显变窄；窄布局下底部统计也会截断。它的计划入口在输入区上方，和用户对本产品的明确要求不同。需要保留本产品已确认的规则，不能原样照搬所有位置、比例和选项。

### 对用户截图中索引设计的具体判断

刻度应保持低存在感；只有当前轮次、指向目标和正在运行的任务需要显著区分。预览卡片用于帮助选择目标，出现位置必须与那条刻度对应，不能让用户在另一个位置寻找结果。它不应长期停留，也不应越过输入框或被消息滚动层裁掉。

在窄聊天栏，先保障正文。应根据可用宽度选择更紧凑的定位入口或临时展开，而不是照抄 Harness 的 900px 隐藏阈值，也不是把同样宽的预览永久塞到每一种布局里。具体阈值需在实际主栏宽度上确定，不能拿窗口总宽度代替。

## 实施顺序与退出条件

**第一批：完整阅读工作流。** 一起调整消息/输入区的阅读轴、执行过程高度、轮次索引/预览、跟随与返回最新。使用一份同时包含长输入、长回复、百项工具、错误、中断、压缩和多轮接续的内容验证，避免分散的小修复互相挤占空间。

**第二批：统一详情与子代理。** 先用已有真实工具结果、子代理任务/结论和文件变更建立检查面板；需要完整子会话、模型请求轨迹时，再分别补可验证的只读协议。所有异步读取绑定会话/Run/对象 ID，关闭或切换时忽略晚到结果。

**第三批：全局视觉和辅助页面。** 统一项目树、设置、插件、自动化的字号、行高、间距、选中态和空白态；按使用目的归类设置。启动凭据等待另走原生生命周期改动与对应测试，不能混在 CSS 修补中。

视觉验收必须包含：

- Mac 实际窗口，1440×900、1280×800、1080×680；左栏打开/收起/最窄/加宽，右工具打开/关闭。另检查约 380–580px 的实际聊天栏。
- 指向首/中/末刻度时，卡片跟随目标且在消息区内；长输入不会改变卡片高度规则；键盘、Esc、减少动态效果可用。
- 展开一轮百项操作后，最终回复仍可快速到达；整组、单项和“展开全部”的层次清晰，滚轮作用范围可预测。
- 正在输出时阅读旧轮次、打开详情、返回原位置、回到最新，均不抢滚动位置；重连和压缩后身份不变。
- 多个子代理中切换、任务完成、失败/取消、旧结果延迟返回、切换会话，均不串内容；顶部入口不影响输入框位置。
- 同一轮文件产物在下一轮及应用重启后仍可定位；真实不存在的能力明确标示，不伪造请求、用量或完成状态。

现有自动检查作为回归底线保留。下一版完成后增加上述缺失的状态/几何/滚动检查，并做实机阅读验收。本次仅修改审视文档，没有新的产品改动需要重跑构建；上一轮测试结果不能当作新设计已获验收。
