# 桌面 Agent 的安全边界

实现状态：2026-10-25。执行器安装与限制见 [executor.md](./executor.md)。Windows 正式宿主为捆绑 Node + JS bundle；本机启动故障已定位为生成的 EXE/浏览器 DLL 继承低完整性标签，并通过指定构建产物及托管内核代码目录的准备流程修复。已验证真实捆绑 Node 和原生桌面启动链路。该修复不修改整个工作区权限、不提升到管理员、不关闭 Chromium 沙箱；Windows 代码执行器隔离仍待安装验收。

## 工作目录与应用数据

新聊天先等待用户选择文件夹/项目，或明确选择“不在目录中工作”；选择前不创建代码工作目录，也不启动任务。旧会话已有绑定继续使用。每个聊天只有一个主工作目录 `workspace.root`，决定 Node、shell 与文件写入位置；会话临时工作区由应用保留，重启后仍然可用，可在界面复制路径取回文件。

项目可登记多个经原生选择器授权的目录。附加目录通过 workspace_list/read/grep 的 root ID 明确读取，不能将附加目录参数静默用于主目录写入。此只读限制适用于文件工具，不能描述为 OS 隔离；未隔离命令仍具有当前系统用户权限。项目目录更新拒绝运行/排队中的任务并撤销旧授权；目录切换不移动或删除文件。

`projectDir` 是兼容旧代码的内部字段，实际指私有 dataDir；其中保存历史、运行日志、变更记录、附件快照和浏览器数据。它不是模型的第二个代码工作区。切换工作目录不会复制、移动或删除旧文件。

文件工具拒绝目录穿越、符号链接、junction、具有多个硬链接的文件、设备路径、Windows ADS 和常见敏感文件。递归搜索遵循同样边界。外部文件夹不能访问应用数据目录。原生选择器签发短期、绑定会话、一次性的路径凭证，模型不能凭空登记任意根目录。

这些检查降低路径混淆风险，但不能替代基于操作系统文件句柄的完整防竞态实现。恶意本机程序持续替换祖先目录仍是待加强的边界。

## 权限与执行

审批方式（手动/规则自动）与访问边界分别保存；界面使用“请求批准/自动批准/完全访问权限”，并提供只读查看。标准模式下，规则自动审批只覆盖已隔离、禁用安装脚本、访问官方 npm registry 的可信依赖安装，其余未隔离进程、浏览器交互及未知 MCP 需确认。完全访问权限是用户对本会话本次运行的持续授权，本地命令、浏览器交互、页面脚本及已启用 MCP 工具不再逐次审批。详见 [chat-experience.md](./chat-experience.md)。

| 模式 | 文件工具 | 模型生成的进程 |
|---|---|---|
| 只读 | 读取当前根内的普通文件 | 拒绝 shell、脚本、安装依赖及远程修改 |
| 标准（默认） | 允许在当前根内编辑 | 隔离可用时按策略运行；需要联网时审批。隔离不可用时，每次明确申请宿主机执行 |
| 完全访问权限 | 同上；命令可使用当前用户的文件访问权限 | 命令、浏览器和已启用 MCP 直接执行，不再逐次审批 |

宿主机权限只在本次应用运行有效，恢复聊天时降为标准。旧的 danger/autonomous 值也迁移为标准。

`Session.execute()` 在实际启动前作决定，`Executor` 是模型进程的统一启动入口。脚本执行、shell、npm 和旧导出自测都属于代码执行。cwd、环境变量过滤和 Node vm 均不是隔离边界。沙箱启动失败不会自动转为宿主机执行。

确认卡显示命令、目录、输入与联网目的地。宿主机执行不能用一次批准覆盖整个 shell 类别；隔离下允许记住的动作绑定命令、输入、工作区版本和目的地。执行脚本会展示源码，并在审批后检查脚本版本。浏览器操作绑定当时的标签页与 URL；MCP 调用在审批后重查服务定义，目标发生变化则取消本次动作。审批有有效期，中断会取消等待并结束所属后台进程。

进程默认不继承模型 API Key、HOME、SSH 或云凭据环境。运行 HOME、临时目录和 npm 配置单独创建。未隔离的进程仍可使用系统用户权限访问磁盘与网络，过滤环境不会阻止它主动读取用户文件。

SRT 后端固定为 `@anthropic-ai/sandbox-runtime@0.0.81`。Windows 支持仍属上游实验能力；本机未安装其运行账户，因此已验证的是“检测失败 → 明确审批”，未宣称验证过 Windows OS 隔离。不能把本实现描述为 Codex 的原生 Windows 沙箱。浏览器与用户批准的 MCP 服务属于另行信任的进程，不在代码执行器沙箱内。

## 浏览器与 MCP

默认产品工具包括文件、执行、计划、提问、上下文、受限研究子代理、目标进展和通用浏览器。调试工具通过 discover_tools(debugger) 按需连接，并与可视浏览器绑定同一个 CDP targetId。旧的专用 AST/VMP 模块仍保留作兼容，不自动注入反调试脚本，也不自动保存网页脚本。网络记录在打开浏览器时默认开启，用户可暂停。

浏览器快照是非可信内容，不能授予权限。点击、填写、按键可能修改网站数据，必须通过宿主动作审批；只读模式拒绝它们。浏览器使用应用自己的配置目录，不直接复用用户日常浏览器的 profile。

网页求值单独审批；调试工具的本地输入/输出仍经过工作区、敏感文件、链接和只读校验。研究子代理仅能列举、读取、搜索工作区，不继承写入、执行、调试器或递归创建能力。长期目标只能由用户命令建立，绑定工作区、有停止/预算边界，重启后暂停，不提高权限。完整边界见 [browser-harness.md](browser-harness.md)。

用户添加的 stdio MCP 服务以系统用户权限启动。导入默认关闭，只有被明确保存或启用的服务配置获得启动信任；变更命令、参数、环境、地址等会改变指纹。批准一个配置不会批准其余配置。标准模式下远程工具按未知外部动作审批，完全访问权限直接执行已启用的工具。工具名包含必要的摘要，避免截断或字符替换造成身份冲突。

## 可恢复性与文件改动

技能和记忆通过专用管理工具按用户/项目/会话范围保存，索引有数量与长度上限，正文按需读取。持久管理在标准模式下明确审批、只读模式下拒绝写入；已保存内容不授予执行权限。Agent 管理 MCP 的返回值不包含其他服务的环境变量或请求头。自动化固定绑定当前会话，不能借管理工具转绑其他会话或继承完全访问。

Run 状态与事件 journal 落盘；journal 先 fsync，再更新快照。启动时从 journal 恢复遗漏状态，将未完成的 Run 标为 interrupted，不重放副作用。重新连接读取后端历史和待批动作。聊天队列会保存，重启后需用户选择继续或清空。

同一规范化根目录同时只允许一个写入 Run。文件编辑记录 before/after 与内容哈希；覆盖前检查旧版本，新文件用排他创建方式提交。撤销只允许当前内容仍匹配该变更结果。终端与其他程序产生的文件变化不在此记录中，需通过 Git 查看。

自动化等待实际 Run 完成。遇到新权限或用户问题，立即标为 needs_attention，不自动提升权限，也不等待无人点击的确认框。

## 凭据与渲染层

模型密钥存系统凭据库；渲染进程只接收 hasKey。Rust 从凭据库读取后，使用 sidecar 私有密钥生成 AES-GCM 信封，前端转发密文。`secret_get` 不再注册为原生命令。新增密钥在用户输入期间仍会存在于设置表单内；MCP 自定义 env/header 目前属于可信设置数据，不要误称所有凭据均已进入 vault。

Markdown 原始 HTML 转义，CSP 限制脚本来源。sidecar 只监听 loopback，并校验 Origin 与启动票据。渲染进程及拥有这些票据的本机程序处于可信边界内；应用不承诺抵御同用户权限恶意进程或已被控制的渲染进程。

## 已知依赖风险

本次升级 MCP SDK 至 1.32.2，并替换有 ZIP 链接问题的解压依赖。剩余 `npm audit` 的 3 条 high 来自 SRT 聚合项及其 node-forge、Zod 依赖。node-forge 的 RSA 校验问题尚无修复版本；本实现不启用 SRT TLS 终止。SRT 的旧 Zod 仅解析受宿主约束的策略配置。它们仍需跟进上游升级，不能标记为“审计清零”。

发布前仍需在安装了隔离后端的 Windows 测试机验证目录外读写、网络拒绝、取消和进程树退出，以及原生文件夹选择器、凭据库与安装包升级流程。
