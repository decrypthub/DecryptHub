日期：2026-11-02，2026-11-03 继续实施。参考提交：`ce7073d51254c26cd63b22a60835b8f948deb447`；桌面基座：`da01a383b7d93120ac70c3f58efa2afcaca99c2d`。分析针对这两个版本及开工时桌面端已有的未提交工作，不代表后续上游版本。

## 结论与边界

本轮完成了核心执行链路的源码对照和第一批实质改造。重点是宿主如何组织上下文、资源和持久状态，以及工具真正执行时的行为。没有按功能名字或文档概念推测实现，也没有据此声称已经达到某个一致性百分比。

按用户要求保留的产品边界：浏览器继续使用自定义 WDH；不移植 Agent 预设选择；插件保留 MCP 与自定义组件，不复制完整 Cordis 插件生态。Tauri/Rust、Node sidecar 和 React 的分层保留。DeepSeek Harness 参考仓只读。

本轮尚不等于完整 DSH 功能替换。文末单列尚存的差异和未验证范围；这些没有被算成“通过”。

## 1. Agent 主循环、环境与自我认知

**参考实现。** `packages/core/system-prompt/src/index.ts` 的提示章节/上下文生产者注册和排序；`packages/core/agent-loop/src/runtime-context.ts:1–180` 的持久上下文接纳、变更与清除；`packages/context/harness-dev-context/src/index.ts:1–160` 区分源码位置、cwd 和实际产品入口；`packages/context/time-context/src/index.ts:1–130` 提供时间事实。

**原有差异。** 动态状态拼进用户消息，应用状态、用户指令和模型输入没有清晰来源边界；工具发现、权限审批是否有监听者与实际执行能力可能不一致。只声明产品身份，不足以回答当前目录、权限、模型和可用资源。

**实施。**

- 新增 `sidecar/agent-context.mjs`，环境与项目指引作为带 `source` 的持久 `continuation` 事件接纳，不改写用户原文；压缩覆盖快照后重新接纳当前事实。
- 环境快照包含 OS/架构/Node/实际运行入口、cwd、项目和聊天 ID、模型/协议/思考档位、当前权限、审批可用性、委派深度、授权根、实际已注册工具、用户命令以及技能/记忆索引。不记录密钥。
- 每一步冻结模型配置、凭据和能力；同一步的重试、图片投影与环境说明使用同一份快照，切模型在下一步生效。
- 工具表按名字稳定排序；保留按需工具发现。可用工具描述和执行权限分别由注册表与策略判断，发现工具不授予权限。
- 普通对话不把宿主快照显示成用户发言；原始历史仍保留，便于复核实际请求上下文。

**验证。** 真实 Agent 循环检查用户原文、规则增量、持久化恢复和 UI 投影；发布版真实模型已读到根规则、子目录规则、项目记忆和文件系统技能。

## 4. 侧栏终端与文件管理

**参考实现。** `client/ui-sidebar-files/src/client/{index,directory-node,face}.ts`，`api/workspace-files/src/index.ts:1–135`；`client/ui-sidebar-terminal/src/client/index.ts:1–120`，`terminal/terminal/src/types.ts:1–150`；`terminal/terminal-bash/src/session.ts:535–617` 的后端前台进程/输入等待证据，及 `shell/tool-bash/src/index.ts:1–135` 的执行语义。

**文件侧栏。** 当前代码已有独立文件视图、逐层目录加载和文件状态接口。本轮没有把这些既有未提交工作算作新增成果。侧栏与 Agent 使用相同工作区身份；实际 UI 已显示新生成的验收文件和原有目录。写入与撤销继续走宿主校验。

**终端。** UI 交互终端与 Agent 持久终端复用 PTY 生命周期；一次性/后台脚本使用执行器与作业存储。新增/修复 cwd 传递、单次交互互斥、取消等待、输出滚动窗口的绝对游标及丢失提示，避免旋转缓冲区后永远读不到新输出。PowerShell 的 APPDATA/LOCALAPPDATA 固定到私有执行目录，避免把模块缓存写进用户项目。

没有把“输出像提示符”当成 `stdin_read` 的证明。WinPTY 当前没有 DSH 所用的前台输入阻塞探针；这种情况下返回 `inferred_idle` 或 `timeout`，另附提示符线索。`session_exit` 表示终端进程退出，不能用它表示一条 shell 命令刚执行完。

**验证。** 真实 PTY 输入/输出、多个终端隔离、关闭聊天清理终端、等待审批时关闭、取消等待、输出滚动，以及提示符样式的普通输出不被误报为确定的 stdin 等待。发布版侧栏已实际启动 PowerShell，cwd 为隔离验收工作区；没有通过 UI 输入终端命令。

## 6. 计划、子代理、目标与命令

### 计划

依据 `plan/plan-mode/src/index.ts:1–440`，计划是协作状态，与文件/执行权限分开。`PlanMode` 持久化 active/pending/entered/revision；运行中选择在下一步边界生效。`exit_plan_mode` 进入过计划后保留在已接纳工具表中，但仅当前计划状态允许执行。

计划提交为完整 Markdown，UI 等待明确“批准计划并实施”；批准只改变下一步，不能在当前工具批中途切换。跳过/取消/超时结束本轮等待，不反复追问或继续执行本批余下操作。计划 UI 使用 Markdown 滚动正文，模式提示随实际状态清除。较旧历史事件不能覆盖懒加载前用户刚选的新状态。

计划提示约束不等于权限沙箱。实际 UI 验收确认：批准前目标文件保持原内容；批准后才编辑并写验收记录。

### 子代理

依据 `subagent/subagent/src/{types,depth,child-agent,manager}.ts`、`subagent/subagent-fork-in-process/src/index.ts`。原先只有只读研究助手，本轮改为可继续的通用委派：独立历史与终端/进程资源，固定创建时权限、工作区身份和模型路线；额外审批直接拒绝，不共享浏览器。

fork 使用截至最后一个完整 `turn-end` 的精确事件前缀，不以短摘要冒充 fork；复制该前缀引用的附件和长输出。深度不能因冷恢复变浅，并发额度跨后代共享。去掉自造的隐形步骤/时间/输出预算，采用用户设置。父代理结束前等待子代理并核验整合；后代用量计入所属目标，每次继续分别计费，不重复累计旧轮用量。

验证包括实际子代理写文件、权限创建后固定、继续原历史、后代用量、父代理等待。真实发布版已完成一项只读委派，父代理随后独立复核。

### 目标

依据 `goal/goal/src/{types,index}.ts`、`goal/tool-goal/src/{authority,index}.ts`。提供 `get_goal/create_goal/update_goal`，更新使用准确 ID/revision；来自用户直接接纳的长期任务可以创建，不强迫用户必须输入固定关键词。自动目标轮次和子代理不能自行替换用户目标。

默认上限 256 轮；暂停/恢复不清零累计轮次；阻塞报告有至少三轮的自动审计门槛，不因一轮没有调用工具便自行判定 blocked。用户暂停的目标由用户恢复；达到预算或工作区失效会停止接续。完成前等待子代理并核验。旧 `goal_update` 留在兼容组，不作为新模型的默认接口。

真实 UI 已通过 `/goal` 启动核验，模型读取目标与文件、检索后调用新目标工具完成。主循环/队列/driver 的故障与预算回执仍独立持久化。

### 命令

依据 `interaction/commands/src/index.ts:1–85` 的注册思想。`sidecar/commands.mjs` 与 UI 共用命令元数据，并注入宿主资源说明；`commands-list` 返回同一份定义。`/plan` 对接真实协作状态；`/goal` 对接目标域；`/agent` 对接通用委派。未知斜杠文本保留为普通输入，供已发现技能调用处理，不在前端一律吞掉。
