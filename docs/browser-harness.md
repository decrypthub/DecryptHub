# 浏览器与 Harness：当前实现及边界

更新于 2026-10-25。

浏览器内嵌路线、显示生命周期和后续开发边界见 [browser-architecture.md](./browser-architecture.md)。

## 使用方式

右侧只保留浏览器、网络请求、工作区文件。打开浏览器后默认抓包，可暂停；主代理可用 `browser_requests` 和 `browser_request_detail` 读取与界面相同的数据。工作区文件内有可选的 Git 改动区，未初始化仓库或没有 Git 时不显示；没有在界面继续维护一套独立于 Git 的撤销系统。

浏览器地址栏的“打开 / 前往”和关闭按钮分离，导航有加载状态及持久错误提示。会话隔离配置存放于该聊天的应用数据目录，避免依赖系统 TEMP。原生窗口嵌入、画面串流都为 AI 操作边框预留 4px；光效来自实际工具执行事件，等待审批时不会伪装成正在操作。

点击、填写和按键命中断点时，工具返回“输入已发送、网页暂停”，不自动恢复、不重复发送，也不等待到 Playwright 超时。暂停时优先使用断点现场和求值工具；界面提供“恢复网页执行”，模型中断后用户也能继续操作。

模型上下文容量优先读取当前渠道下选中模型的容量元数据，不受旧 provider 镜像覆盖；未配置容量时按模型名推断并标明。DeepSeek V4/V4.1/Flash 按官方 API 的 1M 容量识别，较旧模型不扩大。参考 [DeepSeek 模型规格](https://api-docs.deepseek.com/quick_start/pricing/)。聊天栏保留用量查看，移除调整窗口的滑块，运行参数页也移除重复的窗口覆盖。自动压缩和 `/compact` 保留。

## 内核与调试

系统 Chrome / Edge、自定义 Chromium 程序路径、Chrome for Testing、CloakBrowser 和其他 GitHub Release 压缩包可选。自定义路径错误时直接报错，不会悄悄换成另一个程序。GitHub 支持仓库、版本标签、Release 文件名；没有唯一的平台匹配时要求指定文件名。

下载在独立 staging 目录进行，限制大小并拒绝压缩包路径越界、链接和特殊文件，完整成功后才更新安装索引。CloakBrowser 必须验证官方 Ed25519 签名、清单版本绑定和 SHA-256；其他仓库使用 Release 的 SHA-256 digest（若提供），否则明确只标为“已计算 SHA-256”。旧安装不会在下载失败时被覆盖。

从 GitHub 下载的内核经过独立启动、CDP 和画面检查后，才自动切换为当前选用内核。设置页也可单独测试及修复已安装的托管内核。2026-10-25 已定位本机 `0x80000003` / `0xC0000022`：桌面 EXE、捆绑 Node 与浏览器 DLL 继承工作区的低完整性标签。现在构建与安装流程准备指定产物的普通用户完整性，保持 Chromium 沙箱启用；不会修改整个工作区。CloakBrowser 官方公共 Release `chromium-v146.0.7680.177.5` 已通过签名验证、真实原生启动链路、有头画面、抓包和调试器测试。已运行的旧桌面进程仍需完全关闭后重启，详见 [executor.md](./executor.md)。

`discover_tools(debugger)` 按需连接 vendored js-reverse-mcp。保留源码、搜索、文本 / XHR 断点、暂停现场、单步、求值、控制台、WebSocket 等工具；页面导航、点击和标签页选择仍归 BrowserManager。桥接通过 **CDP targetId** 绑定当前标签页，防止两个客户端的页签顺序不同而调试错页。桥接本地输入/输出路径再次经过工作区、敏感路径、硬链接和只读校验。网页求值需要宿主审批；连接中断不会重试结果未知的修改。

上游代码 Apache-2.0 归属保留；本地 `select_page` 添加仅供桌面桥接使用的 targetId 选择。参考：[js-reverse-mcp 工具列表](https://github.com/zhizhuodemao/js-reverse-mcp)、[CloakBrowser 官方下载实现](https://github.com/CloakHQ/cloakbrowser/blob/main/js/src/download.ts)。

## 输入框命令

输入 `/` 展示候选，方向键选择，Tab 补全，Enter 执行，Shift+Enter 换行，Esc 关闭。命令不会被当作普通提示词传给模型；失败时保留原输入。

| 命令 | 行为 |
| --- | --- |
| `/goal 目标` | 保存目标并持续推进；完成需主代理显式报告已验证结果 |
| `/goal pause`、`/goal resume`、`/goal clear` | 暂停、继续或结束目标；也有界面按钮 |
| `/compact [重点]` | 手动压缩上下文，失败保留指令 |
| `/agent 任务` | 启动独立上下文的只读研究子代理 |
| `/agents` | 查看子代理状态、结果和取消入口 |
| `/status` | 查看当前工作区、权限、浏览器、目标 |
| `/stop` | 停止主代理、子代理，暂停目标，清空下一轮队列 |
| `/new`、`/help` | 新建对话、查看命令 |

普通任务默认没有工具轮数或 Token 预算，持续运行至完成或用户停止；旧默认 40 轮迁移为不限，旧自定义值保留。运行设置中可主动填写预算，0 表示不限。相同工具、参数及错误连续重复三轮时提示改变方法，六轮时保存进展并暂停；成功的重复读取不触发该保护。自动压缩成功后可随上下文增长反复触发，只限制连续失败次数，不再限制整个任务仅压缩两次。

`/goal` 默认也移除隐藏的 5 轮、15 分钟、20 万 Token 限额，采用用户设置的可选 Token 预算。子代理的最终 usage 计入所属目标的本批预算，旧批次晚到的结果不会扣除新批次预算。在途请求和收尾可能越过设置的预算；预算到达后暂停，不自动提高权限。退出或重启后保存为暂停，不重放副作用。目标绑定工作区，换目录需要先暂停，跨目录不能直接恢复旧目标。研究子代理仍使用独立、受限的研究预算。

轮数限制是一种可选的运行控制，并非 Agent 循环的必需条件。参考 [Claude Agent SDK 循环与预算](https://code.claude.com/docs/en/agent-sdk/agent-loop)。

文件面板按层读取目录，文件夹默认折叠，支持空目录、方向键、手动刷新、文件预览和发送附件。Git 改动单独读取，Git 不可用不影响目录浏览。会话菜单提供复制稳定 ID 与对话 Markdown，顶部不再显示会话信息按钮。后台诊断接口仍保留供排查，不进入日常对话布局。新建普通会话使用 UUID，旧短 ID 与主会话 `main` 保留以兼容原有数据；运行 journal 和侧车日志以会话/运行 ID 关联。

研究子代理最多并行 3 个，各有独立历史、10 步、5 分钟和 4 万 token 预算；达到上限标记为 limited。只提供工作区列举、读取和搜索工具，不共享浏览器、断点、执行器、写工具或递归创建能力。主代理通过 `agent_spawn / agent_wait / agent_list / agent_cancel` 管理，必须验证子代理结论。停止、关闭聊天或父任务结束会取消相应子任务；重启保留已完成结论，未完成任务标记中断。

这是受限研究子代理和有预算的目标执行器，尚不包含可写代理的 Git worktree 合并、跨设备调度或无限后台自主运行。

## JSVMP：能力缺口与建设顺序

根据上游工具清单及当前 vendored 实现，js-reverse-mcp 是浏览器观测与调试层，不提供通用的 JavaScript VM 去虚拟化引擎。源码、调用栈和局部变量回答“现在在哪里、值是什么”；它们不能直接还原虚拟指令集、解释器状态机和字节码语义。

复杂目标容易暴露以下缺口：

1. **高频暂停效率**：逐次 CDP 往返和串行工具锁不适合几万次 dispatch；反复把大对象和压缩源码送入上下文也会挤走有效证据。
2. **轨迹不足**：断点现场与网络记录不能代替有输入关联、可过滤、分块持久化的 VM 执行轨迹。异步回调、Worker、WASM 和动态生成代码还需要分别建模。
3. **语义恢复不足**：定位到 dispatcher 不等于知道 opcode 的栈效应、寄存器状态和 handler 语义；缺少字节码提取、控制流、差分执行、切片及去虚拟化过程。
4. **验证闭环不足**：模型的猜测需要和固定输入、真实输出、脚本版本 hash、环境条件绑定。漂亮的分析文字不能代替回放通过。

建议按以下顺序建设专用分析工具组，而不是把全部逆向工具永久塞入模型上下文：

- **P0：证据与回放基线**。冻结请求样本、输入输出、脚本 hash、页面环境，给每项结论标记证据、假设、验证状态。
- **P1：有界轨迹采集**。只记录选定 dispatcher / handler 的寄存器、栈、PC 与关键读写，支持事件预算、分块文件、过滤和断点续采；先在少量已知 VM 样本上验证观测开销。
- **P2：VM 中间表示**。识别指令边界和 handler，保存 opcode 语义与栈效应，进行差分验证，再逐步构造 CFG 和代码恢复；对未知 handler 明确保持未知。
- **P3：评测驱动代理编排**。研究子代理分别分析 dispatcher、handler、数据依赖，主代理选择实验、采集和验证。用成功率、样本回放一致率、暂停次数、模型调用与 token 成本衡量收益。

本次没有实现通用 JSVMP 去虚拟化，也没有把旧版启发式 VMP 工具重新包装成这种能力。

## 本轮验证

`browser-debugger.test.mjs` 使用真实 Chrome 验证导航、默认抓包、脚本读取、文本断点、局部变量求值、单步、XHR 断点、恢复后的响应体、切换页签及路径越界；另测 Windows 有头模式、Chrome PID 与帧生成。`kernels-git.test.mjs` 验证失败更新保留旧内核、Git 子目录范围及敏感文件过滤。`harness-lifecycle.test.mjs` 验证目标继续/停止/恢复、子代理上下文隔离与并发取消。

`check-ui.mjs` 通过本地模拟模型，在深浅主题实际发送浏览器工具、目标与子代理任务，检查光效生命周期、画面帧、网络响应、命令键盘交互、结果显示和页面刷新恢复。它不代表真实模型在 JSVMP 任务上的成功率。

本机最终结果：195 项运行时测试全部通过、深浅主题 UI 契约通过、UI 静态检查通过、原生桌面调试构建通过。新增验证完全访问权限下的真实浏览器填表/点击不申请批准、本机命令不申请批准、超过 40 轮继续、反复压缩、模型容量优先级、目录浏览和会话诊断。真实捆绑 Node 通过发布 JS bundle 的浏览器与 debugger 冒烟；隐藏原生窗口的完整桌面链路通过系统 Chrome 和 CloakBrowser 的有头启动、DOM、请求响应体、源码搜索及旧内核修复。Windows 代码执行器的 OS 隔离仍未完成安装验收，不能和 Chromium 自身沙箱混为一谈。
