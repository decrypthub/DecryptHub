## 日志契约与迁移

- `.agent-history.json` 在首次写入时变为 v4 存储指针；实际事件保存在 `.history/history-<随机标识>.jsonl`。事件语义仍为本产品 v3，不冒充 DSH 自身的事件格式。
- v1/v2/v3 原记录在首次写入前只读；迁移先独占写入、写完整新代际并 fsync、复读验证，再发布指针。原 JSON 按原字节保存为 `.history/legacy-<sha256>.json`。旧应用拒绝 v4，避免读旧视图后覆盖新日志。
- 正常写入只追加新记录，保留连续序号；重置/显式改写前缀发布新代际，旧代际不覆盖。只读扫描不修改文件；只有取得写入权后才截去不完整的最后一行。完整记录损坏、序号不连续、未知必要事件和坏指针均拒绝加载，不能回落为空或旧代际。
- 写入权通过本机 Node SQLite 的 OS 写锁事务保持，进程死亡由内核释放；不以 PID 文件或超时抢占活写入者。它适配 DSH 的写入租约语义，但后端不是上游 Win32 semaphore/POSIX flock。另对本产品的共享 sessions.json 索引持有数据目录租约，防止两个 sidecar 并写同一份索引。
- 原始事件保存为不可变快照。压缩计量在提交前计算完，不再提交后修改旧事件对象。旧快照即使第一次保存被拒，重试也不能变成空白新句柄覆盖新记录。
- 应用恢复时给未结束的尾部补充持久回执，区分工具未记录开始和结果未知；不自动重放副作用。新增调用开始日志为这项区分提供证据。

## 检索与对话操作

- 用可重建的 SQLite 派生索引替换字面子串评分，保留实时会话优先、冷读不启动 Agent、同工作目录授权、当前步骤排除和摘要 current/shadowed 追溯。
- Unicode 片段、字面查询转义、SQL 参数/谓词预算、FTS 候选与排序直接移植。索引文件有 application_id/schema 校验，拒绝重置外来数据库；索引损坏或错误不能伪装成无结果。
- 旧侧栏项目/会话搜索也能读取新 JSONL；读取预算仍作用于真实日志大小，不能只计算小指针文件。新日志/索引/租约纳入私有元数据保护。
- 分支采用当前默认供应商、模型及本产品的默认思考选择；不再复制源聊天的旧模型选择。继承长度是精确前缀长度，后接 seed 标记和必要的 forked 收尾事件。
- 可编辑较早的用户消息，包括后面已有工具结果的消息；编辑始终创建分支，原日志和已有文件改动保留。附件可复用/调整，附件内容和元数据校验后独立复制，不依赖父会话继续存在。
- 移除 100 会话的创建与恢复截断；重启仍恢复完整索引。

## 尚存差异

本轮不是 DSH 全套持久化提供者的逐字移植。尚未接入它的压缩 JSONL、多格式迁移目录与验证 worker、完整稳定游标/导出接口和写入合批调度；物理格式、全局索引及租约后端采用本产品适配。移除 100 会话截断不代表大规模 UI 优化：界面仍加载所有聊天快照，未验证大量长聊天的长期性能。未做断电/磁盘硬故障及全部平台实测。大文件修改、更多技能/运行资源、供应商和命令机制继续在后续清单内。
